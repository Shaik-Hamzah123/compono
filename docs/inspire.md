# Inspire

Point Inspire at a folder of `.pptx` files someone already likes and it
scans them into a style profile/skill an agent can read before generating
a *new* deck with `compono` — so the new deck adopts similar practices
loosely, without being a literal copy of any source deck.

## What gets extracted — and what never does

Inspire extracts only measurable structure/style: fill-color palette by
frequency, font family/size pairs by frequency, shape-type mix, average
margin/gap spacing, and detected grid column patterns (each with a
confidence score — a shaky pattern is omitted, never reported as a
guess).

**Hard rule: it never extracts literal text or images.** No run text,
table cell text, or image bytes from a source deck is ever read into the
profile. This is what makes scanning your own old decks safe by default
(a style profile shouldn't accidentally become a searchable copy of old
client names/numbers), and what makes sharing the result with teammates
low-risk — the profile never carried the original content in the first
place.

## Personal vs. team — one mechanism, no separate modes

Inspire has no notion of deck ownership, only content. Point it at your
own folder of decks and you get a personal style skill; point it at a
team's shared drive and the identical code produces a team style skill
instead. Sharing the result needs no new distribution mechanism — it's a
skill folder, shared the same way any other `.claude/skills/` skill is.

## CLI

```bash
compono inspire scan decks/ -o skills/inspire-myteam/ --name myteam
```

Scans every `*.pptx` under `decks/`, aggregates facts across all of them
(a fact must recur in at least `--min-repeat-ratio` of the decks, default
`0.5`, to be promoted from "seen once" to a real practice), and writes:

```
skills/inspire-myteam/
├── SKILL.md       # agent-facing instructions, templated from the
│                   # aggregated facts (recurring palette/fonts/layout
│                   # habits) — written as guidance, not a hard template
└── profile.json    # the full structural profile: palette/font
                     # frequency, spacing, per-slide grid detections
                     # with confidence scores
```

A `.pptx` file that fails to open is skipped with a warning, not a
crash — the scan continues over the rest of the folder.

## Python API

```python
from compono import aggregate, scan_deck, write_skill

profile = scan_deck("one_deck.pptx")       # a single deck's profile
merged = aggregate(["a.pptx", "b.pptx", "c.pptx"])  # recurring vs. one-off
write_skill(merged, "skills/inspire-myteam/", name="myteam")
```

`scan_deck`/`aggregate` are pure inspection functions — they never modify
the scanned files. `write_skill` is the only function that writes to
disk, and only to the folder you point it at.

## Known limitations

- Grid detection is a naive geometric heuristic (row-clustering by
  y-position, checked for near-equal widths and evenly spaced gaps) — it
  works well against clean, grid-based layouts (including anything
  `compono` itself rendered) but will find fewer confident patterns in a
  genuinely irregular, hand-authored deck. That's the intended behavior:
  "no confident pattern found" is a valid, expected outcome, not a bug.
- `SKILL.md`'s prose is templated directly from the structural facts, not
  generated by an LLM summarization pass — it can only ever say what the
  numbers support, nothing richer (e.g. no visual-density judgment from
  actually looking at a rendered slide).
- Table/chart cell text is never read (by design), which also means a
  deck's tabular/chart-heavy style (e.g. "always uses 3-column tables")
  isn't yet captured beyond the general shape-type mix count.
